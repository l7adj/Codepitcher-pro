# CodePatcher

تطبيق ويب (PWA) واحد بلا أدوات بناء. يعمل بفتح `index.html` مباشرة أو من خادم.

## البنية
- `index.html` — الهيكل (HTML فقط) + روابط التصميم الخمسة بالترتيب + وسوم `<script>` بالترتيب.
- `css/` — نظام التصميم الموحّد المكوّن من 5 ملفات فقط:
  1. `css/tokens.css` — **(الملف المركزي #1)**: الخطوط (`IBM Plex Sans Arabic` و`JetBrains Mono`)، المقاسات، المسافات، كثافة الواجهة (`data-density`)، استدارة الحواف (`data-radius`)، وألوان التمييز (`data-accent` ومنها `gold`).
  2. `css/themes.css` — **(الملف المركزي #2)**: إدارة 6 ثيمات مركزية (`dark` أوبسيديان، `royal` ملكي ذهبي، `light` خزفي، `ocean` محيطي، `paper` ورقي، `contrast` تباين عالٍ عبر `data-theme`) مع جسر كامل للمتغيرات وتلوين الكود وأيقونات الملفات.
  3. `css/components.css` — المكونات القابلة لإعادة الاستخدام (الأزرار، الحقول، النوافذ المنبثقة `.modal/.sheet`، صفوف القوائم `.mi/.issue`، الشارات، بطاقات الأخطاء، القوائم السياقية، والإشعارات).
  4. `css/layouts.css` — تخطيطات الشاشات (الإطار العام، الرئيسية مع أحدث الملفات، المحرر، مستكشف الملفات، استوديو الباتشات، المعاينة والكونسول، السجل، والإصدارات).
  5. `css/responsive.css` — التجاوب وحالات التشغيل (`body.sym`، `body.runfs`، `body.side-open`، الهواتف الصغيرة، الأجهزة اللوحية، وحاسوب IDE بشاشتي Bento والباتشات المنقسمة).
- `js/NN-اسم.js` — سكربتات عادية (ليست ES modules، لأن الملف المباشر `file://` لا يدعمها). تتشارك النطاق العام، والرقم هو ترتيب التحميل. دوال القوالب المشتركة للواجهات (`uiRow`، `uiScroll`، `uiNote`، `uiEmpty`، `uiSub`) موجودة في `js/06-ui-core.js`.
- `sw.js` — service worker (`codepatcher-v12`)، يخزّن كل الملفات.
- `js/16b-text-bundle.js` — تصدير المشروع كنص واحد (مع خريطة وتقسيم لأجزاء) واستيراده.
- `Tools/check.js` — يعمل كـ ES module عبر `npm run check` من جذر المستودع، ويفحص صياغة JS والتسجيل وترتيب التحميل والأسماء العامة المكررة.

## قواعد عند التعديل
1. لتغيير لون، ثيم، ارتفاع زر، كثافة، استدارة حواف، أو مسافة عبر التطبيق بالكامل: عدّل في `css/tokens.css` و`css/themes.css` فقط دون لمس ملفات JS التشغيلية.
2. ملف جديد: أضفه في `index.html` وفي قائمة `sw.js` مع رفع رقم `codepatcher-vN`، ثم شغّل `node Tools/check.js`.
3. استوديو الباتشات والإصدارات والمعاينة والسجل تشترك في إيقاع تخطيط واحد؛ اضبط المقاسات العامة من `tokens.css`، ونقاط التحول وسلوك الهاتف من `responsive.css`.\n4. مستكشف الملفات RTL-first: يفتح من الحافة اليمنى على الهاتف، ويستخدم أزراراً دلالية للملفات والمجلدات والقوائم السياقية. غيّر هندسته من متغيرات `tokens.css` وقواعد `layouts.css`/`responsive.css`، لا منطق الملفات في JS.\n5. لا تخلط منطق التشغيل داخل CSS، ولا تضع تنسيقات `style="..."` داخل HTML أو قوالب JS (استخدم فئات `components.css` ودوال `06-ui-core.js`).
5. `29-patch-history.js` يلفّ `runPatchEngine` و`applyPatch` ويجب أن يبقى آخر وحدة من وحدات المحرك؛ ملف `30-mobile-redesign.js` طبقة واجهة لاحقة مستقلة.
6. بعد أي تعديل: شغّل `npm run check` ثم `npm run build`، وبعدها افتح التطبيق ← الإعدادات ← الاختبار الذاتي.

لحدود مسؤوليات التصميم وقواعد التعديل والاختبار، راجع `DESIGN-SYSTEM.md`.
